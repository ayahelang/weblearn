DNS → GitHub Pages

Panduan lengkap menghubungkan domain atau subdomain ke website GitHub Pages melalui JagoanHosting, DomaiNesia, dan Hostinger. Dibuat agar mudah diikuti dari pemula sampai siap deploy.

KonsepGitHubJagoanHosting DomaiNesiaHostingerSubdomain Troubleshooting

01 — Kenali jenis domain

Domain utama / apex

Contoh example.com. Arahkan root domain menggunakan empat A Record GitHub Pages.

Subdomain

Contoh app.example.com atau www.example.com. Arahkan dengan CNAME ke USERNAME.github.io.

Intinya: DNS provider hanya memberitahu browser ke mana domain harus menuju. File website tetap berada di repository GitHub Pages.

02 — Siapkan GitHub Pages

Aktifkan Pages

Repository → Settings → Pages. Pilih branch dan folder publikasi yang berisi website.

Isi Custom domain

Masukkan domain yang akan digunakan, misalnya example.com atau app.example.com, kemudian simpan.

Konfigurasi DNS

Untuk root domain, gunakan empat A Record berikut. Untuk subdomain, gunakan CNAME.

TypeHost / NameValue
A@185.199.108.153
A@185.199.109.153
A@185.199.110.153
A@185.199.111.153
CNAMEwwwUSERNAME.github.io
Setelah DNS terdeteksi dan sertifikat tersedia, aktifkan Enforce HTTPS di GitHub Pages.

03 — JagoanHosting

DNS Management

Buka pengelolaan DNS

Login Member Area JagoanHosting → Domains → pilih domain → menu DNS Management.

Buat empat A Record

Gunakan host @ dan masukkan masing-masing IP GitHub Pages pada record terpisah.

Buat CNAME www

Host www → target USERNAME.github.io.

Simpan

Tunggu propagasi DNS, lalu periksa kembali Custom domain di GitHub Pages.

Jangan hapus MX/TXT sembarangan. Record tersebut bisa digunakan email, SPF, DKIM, verifikasi layanan, dan kebutuhan lain.

04 — DomaiNesia

DNS / MyDomaiNesia

Pilih domain

Login ke MyDomaiNesia → buka daftar domain → pilih domain yang akan digunakan.

Pastikan nameserver

DNS harus dikelola di provider yang menjadi authoritative nameserver. Jika nameserver diarahkan ke tempat lain, edit DNS di tempat tersebut.

Tambah A Record

Host root @ → Type A → empat IP GitHub Pages.

Tambah CNAME

Host www → CNAME → USERNAME.github.io.

05 — Hostinger

hPanel · DNS Zone Editor

Buka DNS Zone Editor

Di hPanel, pilih domain lalu buka DNS Zone Editor.

Atur root domain

Name @ → Type A → masukkan empat IP GitHub Pages sebagai record terpisah.

Atur www

Name www → Type CNAME → target USERNAME.github.io.

Cek nameserver

Jika nameserver domain bukan milik Hostinger, DNS Zone Editor Hostinger tidak menjadi sumber DNS utama.

06 — Custom subdomain

Untuk website seperti learn.example.com, konfigurasi DNS cukup satu CNAME:

TypeHostTarget
CNAMElearnUSERNAME.github.io
learn.example.com → USERNAME.github.io

Kemudian di repository GitHub: Settings → Pages → Custom domain → masukkan learn.example.com.

Jangan memasukkan URL repository seperti USERNAME.github.io/nama-repo sebagai target CNAME. CNAME menuju host GitHub Pages.

07 — Troubleshooting

Domain belum tersambung

  • Periksa IP dan target CNAME.
  • Pastikan tidak ada record bentrok.
  • Pastikan DNS diedit di provider authoritative.
  • Beri waktu untuk propagasi DNS.

HTTPS belum tersedia

  • Pastikan DNS sudah benar.
  • Tunggu GitHub menerbitkan sertifikat.
  • Setelah tersedia, aktifkan Enforce HTTPS.
Hindari tutorial DNS lama yang tidak jelas. Jangan menambahkan record acak atau menghapus record email hanya demi membuat website aktif.

08 — Checklist sebelum selesai

☐ GitHub Pages aktif
☐ Custom domain sudah diisi
☐ Root domain memakai empat A Record GitHub
☐ www memakai CNAME
☐ Tidak ada record bentrok
☐ DNS dikelola provider yang benar
☐ Propagasi DNS sudah diberi waktu
☐ HTTPS aktif setelah tersedia
